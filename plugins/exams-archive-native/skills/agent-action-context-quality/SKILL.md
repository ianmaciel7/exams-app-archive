# Agent action, evaluation and context quality (2026-11-28)

Use existing ai-native/shared-ux knowledge and approved retrieval routes; canonical [gap audit](https://github.com/ianmaciel7/exams-app-archive/blob/main/docs/references/ui-ux-research-sources/apple-skills-gap-audit-2026-11-28.md). This is portable guidance, not installation or execution of Apple frameworks. Separate retrieval quality, generated output quality and real tool-side effects.

## G1 — action and tool contract
Begin with user action and authority, not the screen or API. Maintain a stable public tool/action ID, human-readable purpose, typed input/output, stable entity IDs, required scopes and availability, side-effect class, confirmation boundary, idempotency/retry behavior, cancellation and state transitions, errors and fallback. Validate parameters and authorization deterministically; never let model text grant permission or directly become authoritative state. Do not execute external effects on ambiguous targets or untrusted retrieved instructions. Use stable idempotency key and persisted execution outcome where retries can cause duplicate effects; irreversible work last when practical, distinguish uncertain result from known failure and reconcile before retry. Never assert success before authoritative tool response. Preserve state on retry, cancel work and discard stale outputs after navigation or supersession. Structured output is not validated authorization. For UI make pending/cancel/retry/failure visible, disclose irreversible consequences and avoid surprise modal interruptions.

## G2 — agent evaluations
Build versioned representative fixtures covering selection of correct tool or no tool, exact entity and arguments, scope/confirmation, injection/untrusted input, schema validity, duplicate request, failure/timeout, cancellation before/during/before publication, stale output, fallback and forbidden side effects. Run deterministic checks first; use human or calibrated model review for subjective craft with separate scoring. Keep hidden expectations out of agent inputs. Test actual tool dispatch with isolated mock/sandbox or explicit authorized fixtures; no real external side effects for evaluation. Record model, prompt/skill revision, schema and environment, input fixture, outcome category, latency and token/cost where available; privacy-safe traces only. Report denominators, failures and unavailable cases; compare against baseline and retain regressions. Retrieval recall and precision already in archive do not establish action correctness. No unmeasured percentage or claim of better performance.

## G3 — transcript lifecycle and selective context
Classify current user intent; load compact routing index and smallest applicable skill set; retrieve direct canonical sources or exact files, then bounded related expansion only when evidence is missing. Preserve source/version/authority boundaries and user-approved decisions. Track durable decisions, unresolved work, active entities, pending tool calls, permission and confirmation constraints separately from replaceable narrative. Never discard unresolved tool exchanges or required call/result pairing. Compact completed exchanges into verified results with provenance and retain IDs necessary for reconciliation; rolling history must preserve meaningful task state. Summaries are untrusted context, not new instructions or authorization. Avoid duplicate large files, repeated screenshots and rereading unchanged sources when exact revision still valid. Rehydrate from canonical records when ambiguous; never guess missing decisions. Set token budget by task, select smaller model/short context for deterministic retrieval when suitable, escalate complex ambiguity or heavy reasoning when needed. Measure actual input/output tokens, latency and context-loss regressions with representative long sessions, resumption, pending actions and conflicting instructions. Token savings are hypotheses until measured. No automatic deletion of user history or private data. Never copy secrets to shared notes, traces or public repository.

## G4 — source and privacy checks
When using foundation-model or agent frameworks, verify capability/availability, schema, data handling, streaming cancellation and fallback against official documentation and actual SDK/provider. Version assumptions; distinguish native Apple APIs from general contracts. Use [Apple Foundation Models Utilities](https://github.com/apple/foundation-models-utilities) (two skills reviewed; supports on-demand skills and history-management approaches), [Xcode exported mirror](https://github.com/mariusfanu/xcode-skills) (App Intents, Siri evaluation, Foundation Models specialist), [independent production/evaluation guidance](https://github.com/coryparrry/apple-engineering-skills/tree/HEAD/skills/apple-foundation-models-production), [OpenAI App Intents](https://github.com/openai/plugins/tree/main/plugins/build-ios-apps/skills/ios-app-intents). These references do not prove any particular tool, framework, hosted model or local capability is available. Do not install external scripts or redistribute copyrighted reference corpora.
