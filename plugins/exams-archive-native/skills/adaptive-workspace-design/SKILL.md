# Adaptive workspace design — operational supplement (2026-11-28)

Read apple-hig-design-craft and the existing app-shell or workspace skill first. This is independent synthesis; the canonical source register and scope are in the [gap audit](https://github.com/ianmaciel7/exams-app-archive/blob/main/docs/references/ui-ux-research-sources/apple-skills-gap-audit-2026-11-28.md). Preserve approved content, stage, and interaction contracts; never silently redesign or change the active repo.

## HIG routing and decision provenance
Start with shared hierarchy, readability, accessibility, state and material foundations. Determine platform, input capabilities, task, viewport/container constraints, existing architecture and deployment target. Load only the relevant platform and component guidance (navigation, layout, toolbar, window, gesture, editing, etc.), then at most one bounded expansion to directly related topics; expand further only for a concrete unresolved question. Recheck current primary Apple guidance when SDK details or exact platform values matter. For web, use HTML, CSS, WCAG and browser APIs; do not import Apple pt sizes, native colors, font licenses or SwiftUI APIs as web rules. Label findings Apple guidance, community interpretation, project choice or unverified hypothesis. Use existing quality and anti-slop gates; not a mandate for Apple styling.

## A1 — continuous adaptive resizing
Define a contract per region: minimum useful content, intrinsic size, preferred range, relative priority, collapse/overflow behavior and focus target. Measure the closest container, not a global device label; use CSS grid/flex, container queries where appropriate, min-width:0 and content-aware wrapping. Avoid remounting the entire shell at breakpoints. Preserve object identity, active tab, selected answer, scroll anchor, draft and keyboard focus; if focus target disappears, restore to an equivalent reachable control. Continuous splitter drag follows pointer with clamping, cancellation restores start; keyboard resizing or equivalent must be available. Test narrow-wide-narrow, zoom/reflow, long localized text, sidebar both sides, rapid resizing, touch and mouse. Verify no clipped essential actions, horizontal page overflow, duplicate tabs or reset selection. Responsive reorganization must not remove capabilities.

## A2 — toolbar priority and overflow
Inventory commands as essential, frequently used, secondary or contextual. Give essential commands a reachable stable location or explicit accessible overflow equivalent; group by task and scope, not decoration. Define deterministic collapse order (labels may shorten only if accessible names persist); reserve overflow trigger space to avoid jitter. Overflow keeps commands discoverable and operable by keyboard/touch; opened menu tracks anchor, Escape closes and returns focus. Test at widths just above/below each threshold and with longer translations, zoom and selection changes. Distinguish location/navigation from actions. A distraction-free mode has a visible or documented recovery path. No hidden critical controls or inaccessible hover-only commands.

## A3 — window, tab and panel lifecycle
Define object ID, view kind, workspace scope and explicit multi-instance intent; reuse matching tab by default and open duplicates only for a deliberate separate view. Maintain local view state (scroll, selection, split widths) separately from durable document state; close disposes subscriptions, timers and pending requests. Define open/reuse, open in new pane, move, close, restore, focus return and unsaved changes. Test reload, multiple authorized workspaces, empty panels, repeated open, close active, history back/forward, keyboard shortcut conflicts and mobile drawer. Web tabs are not OS windows; native scene chrome/commands are platform-specific. Do not expose private restored state across accounts.

## A4 — document and editing lifecycle
Separate draft, dirty, pending save, saved, conflict, error and offline states; only authoritative acknowledgement means saved. Keep stable document ID and version/revision; autosave debounces safely, serializes writes or uses revision guards, prevents stale response from overwriting edits, and preserves recoverable draft on failure. Specify undo scope and grouping; redo invalidates after divergent edits; remote irreversible actions require confirmation/compensation rather than pretend undo. Support cancellation and progress for long import/export; protect against duplicate requests and cross-store partial writes. Test typing during save, offline/reconnect, conflict, close/reopen, undo/redo after save and reload, export failure, explicit recovery. Preserve original file and report destructive reset separately. Native DocumentGroup/UndoManager dependency is not a universal autosave mechanism.

## A5 — multimodal interaction and gesture ownership
For every essential task map mouse, touch and keyboard alternatives (assistive technology where supported). Distinguish focus, hover, active and committed selection. Define precedence/ownership among click, press, drag, scroll, pinch and text selection per region; native controls retain default behavior unless justified. Do not disable all competing recognizers or let one interaction trigger twice. On web use pointer capture only for active direct manipulation and suitable touch-action; preserve scrolling/zoom, handle pointercancel, lost capture, Escape, blur and release outside. Before threshold movement can remain scrolling; intentional drag begins with clear feedback, cancellation restores original state. Avoid hover-only actions and provide non-drag reorder alternative. Test nested scroll, long press vs scroll, drag outside, rapid reversal, multi-touch, keyboard selection and reduced motion. Exact thresholds are project-tested, not Apple mandates.
