# App Shell selection and evidence

Read the shared UX contract and the canonical [taxonomy](https://github.com/ianmaciel7/exams-app-archive/blob/main/docs/references/ui-ux-research-sources/app-shell-taxonomy-2026-11-27.md) and [selection matrix](https://github.com/ianmaciel7/exams-app-archive/blob/main/docs/references/ui-ux-research-sources/app-shell-selection-guide-2026-11-27.md). Retrieve the dedicated concept `ui.layout.app-shell` via archive context resolve/context and public research index when available; aliases include App Shell and tipos de app shell. Use connected GitHub reads when local index is unavailable. The 48 prior labels are mixed categories, not independent official types.

Canonical decision matrix for all 48 previous labels: https://github.com/ianmaciel7/exams-app-archive/blob/main/docs/references/ui-ux-research-sources/app-shell-selection-guide-2026-11-27.md . Before selecting a shell, identify tasks, IA, destination frequency, document independence, simultaneous context, available window width, expertise and input modality. Choose topology, navigation placement, pane semantics, chrome ownership, domain recipe and behavior separately. Use single/focus for isolated tasks; top/bottom/rail for a small stable set of destinations; sidebar for broad/deep IA; list-detail for selection-driven detail; list-detail-detail for a hierarchy; supporting pane for auxiliary context; tabs for independent documents; split for concurrent work; docking or windows only for a demonstrated expert need. Avoid duplicate global/local navigation. Set minimum usable widths from representative content, zoom and localization, not universal breakpoints.

Additional dimensions: SDI (one document per top-level window), MDI (internal document windows), TDI (document tabs, alias/subtype of tabbed workspace), ribbon (command-centric chrome, not document tabs), map + list/detail (spatial content recipe), resource detail hub (resource page template). Do not count these as independent geometry families. Define region roles, scroll boundaries, responsive transitions, state ownership, keyboard/focus/RTL and unsaved work. Compare plausible alternatives via task completion, time, navigation errors, context switches, state loss, perceived effort and accessibility; no fabricated scores or universal thresholds. Record decision and rationale. Distinguish historical project evidence from this general documentary synthesis; no live product validation.
