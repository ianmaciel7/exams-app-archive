## Knowledge catalog

- **Component Intent / Selection Rules** (`intent`): Document purpose, use/avoid conditions, action outcome and alternatives, rather than only names. **Acceptance:** Given submit, save and continue, select the correct action and explain its outcome. Sources: agent-design-madhesh, agent-design-metadata, agent-design-figma-context.
- **Component Behavioral Contract** (`contract`): Specify props, events, guards, transitions, accessibility, responsiveness and composition; separate visual appearance from behavior. **Acceptance:** Given allowed state and trigger, expected next state and side effects are testable. Sources: agent-design-vaeghi, agent-design-spiegel, agent-design-carbon-checklist.
- **State vs Variant / State Matrix** (`states`): Separate configuration axes from runtime states, including valid combinations and error paths. **Acceptance:** Loading+disabled and selected+focus combinations render and behave predictably. Sources: agent-design-feng-variants, agent-design-feng-states, agent-design-vaeghi.
- **Component Anatomy and Slots** (`anatomy`): Define parts, slots, boundaries, required content and semantic relationships before choosing a framework. **Acceptance:** Map each slot to an implementation and test missing/long content. Sources: agent-design-uianatomy, agent-design-curtis-spec.
- **Typed Component Schema** (`typed`): Encode valid values, defaults, references and constraints using structured data; do not rely on name inference. **Acceptance:** Reject invalid enum, unsupported prop and illegal composition in validation. Sources: agent-design-curtis-contracts, agent-design-vallaure.
- **Semantic Token Chain** (`tokens`): Map primitives to semantic intent and component role where appropriate; avoid unapproved raw values. **Acceptance:** Trace token from role to theme value and check light/dark usage. Sources: agent-design-queiroz, agent-design-figma-context.
- **Composition Rules / Design Grammar** (`composition`): Define allowed structures and relationships, negative constraints, dependencies and alternatives; assess the assembled screen. **Acceptance:** Compare whole screen with task and hierarchy, not isolated specimens. Sources: agent-design-lou, agent-design-metadata, agent-design-wolosin.
- **Composition Recipes / Templates** (`recipes`): Provide representative combinations with context, variants, slots and counterexamples; avoid mandatory generic layouts. **Acceptance:** Assemble two realistic flows from approved recipes and identify unsupported cases. Sources: agent-design-horner, agent-design-wolosin, agent-design-lou.
- **Spatial Rhythm / Information Density** (`rhythm`): Define relationships between internal spacing and separation of groups, density by task and size. **Acceptance:** Compare dense workspace and reading layout; no clipping or false grouping. Sources: agent-design-wolosin, agent-design-ixdf-align, agent-design-crosley.
- **Optical Alignment / Visual Weight** (`optical`): Use perceptual correction for icons, typography and alignment; document justified exceptions. **Acceptance:** Inspect rendered alignment at actual sizes and compare with reference. Sources: agent-design-ixdf-align, agent-design-nng-good, agent-design-saglitz.
- **Visual Hierarchy / Art Direction** (`hierarchy`): Prioritize content using scale, weight, spacing, contrast and visual thesis appropriate to product type. **Acceptance:** User can identify primary task; visual references and rendered review support hierarchy. Sources: agent-design-nng-good, agent-design-saglitz, agent-design-openai-delight.
- **Visual Restraint / Container Discipline** (`restraint`): Use grouping and surfaces for meaningful content boundaries, not generic card nesting or decoration. **Acceptance:** Remove unnecessary borders/cards while preserving information and affordance. Sources: agent-design-saglitz, agent-design-openai-frontend.
- **Responsive / Overflow Contract** (`adaptation`): Define container behavior, long content, reflow, scroll, expansion, input modalities and edge cases. **Acceptance:** Test narrow and wide layouts, zoom, long text and actual input behavior. Sources: agent-design-carbon-checklist, agent-design-openai-frontend, micro-vercel.
- **Microinteraction and Motion Contract** (`motion`): Reference existing state, tooltip, motion and workspace behavior catalogs; define trigger, feedback, timing and interruption per component. **Acceptance:** Hover/focus/touch and reduced-motion scenarios work without semantic delays. Sources: micro-vercel, agent-design-carbon-checklist.
- **UX Contract / Cross-screen Coherence** (`flow`): Record user task, behavior, failure recovery and evidence-linked requirements across flow boundaries. **Acceptance:** Follow end-to-end task with errors and return navigation; verify consistency. Sources: agent-design-spiegel, agent-design-nguyen.
- **Progressive Context Disclosure** (`retrieval`): Keep global direction compact; index task-specific specs and fetch only relevant authoritative details. **Acceptance:** Agent finds correct registry/spec with bounded context; unresolved dependency is explicit. Sources: agent-design-horner, agent-design-caillet, agent-design-google-spec, agent-design-wolosin.
- **Machine-readable Context / MCP plus Skills** (`authority`): Separate live component facts from composition, usage and interaction guidance; test tool access and fallback. **Acceptance:** Agent selects existing component from authoritative registry instead of inventing it. Sources: agent-design-wolosin, agent-design-daggett, agent-design-atlassian-eval.
- **Queryable Usage and Anti-pattern Metadata** (`metadata`): Encode use cases, selection conditions, exclusions, rationale and alternatives; preserve prose for nuance. **Acceptance:** Query suitable component and reject documented misuse; avoid treating heuristic as universal. Sources: agent-design-metadata, agent-design-madhesh.
- **Spec-driven Component Development** (`pipeline`): Normalize shared intent and deterministic transforms where feasible; separate authoring, publishing and consumption. **Acceptance:** Compare spec to design/code/docs; verify generated outputs before use. Sources: agent-design-curtis-spec, agent-design-queiroz, agent-design-horner.
- **Specification Round-trip Fidelity** (`roundtrip`): Reconstruct from spec, re-extract, diff dropped/distorted/invented information; include semantic and visual checks. **Acceptance:** Baseline vs re-extracted data highlights losses; no claim of fidelity from schema alone. Sources: agent-design-curtis-roundtrip, agent-design-curtis-contracts.
- **Design System Governance / Drift Control** (`governance`): Define approved source, version and human review; propose missing capabilities instead of silent custom forks. **Acceptance:** Detect invented props/tokens, review gaps, record approved changes and exceptions. Sources: agent-design-pujari, agent-design-vallaure, agent-design-caillet.
- **Design Quality Gates** (`quality`): Review rendered visuals, task fit, states, accessibility, responsiveness and cross-screen consistency before acceptance. **Acceptance:** Evidence matrix records pass/fail/untested and fixes; static screenshot alone insufficient. Sources: agent-design-nguyen, agent-design-figma-context, agent-design-openai-frontend.
- **Interaction and Visual Acceptance Testing** (`tests`): Use isolated initial states and interaction assertions plus visual comparison and end-to-end tasks where relevant. **Acceptance:** Run keyboard/touch, pending/error/empty and responsive scenarios; verify actual outcomes. Sources: agent-design-storybook, agent-design-carbon-checklist, micro-vercel.
- **Context Strategy Evaluation** (`evaluation`): Compare same task and conditions across design artifacts, skills and MCP; measure tokens, latency and quality separately. **Acceptance:** Record baselines, model/version, sample and scope; don't generalize single-task results. Sources: agent-design-atlassian-eval, agent-design-caillet.
- **Design System Completeness Audit** (`completeness`): Check foundations, anatomy, states, behavior, composition, content, responsive, motion, accessibility and verification; use references rather than duplicating all knowledge. **Acceptance:** Identify missing contract fields, evidence and explicit not-applicable cases. Sources: agent-design-designspecs, agent-design-google-spec, agent-design-carbon-checklist.
- **Visual Reference and Evidence** (`reference`): Use relevant rendered examples, reference images and real product structure to guide composition; check rights and distinguish observation from inference. **Acceptance:** Inspect desktop/mobile screenshot and actual behavior; record source and limits. Sources: agent-design-openai-delight, agent-design-openai-frontend, agent-design-crosley.

## Proposed agent-ready documentation layout

Keep DESIGN.md compact: visual direction, global constraints, semantic foundations and links to authoritative registries. Put component contracts, patterns, recipes, motion, accessibility, content/edge cases and quality evidence in task-specific references. Use typed schemas where validation matters; route to actual implementations and test fixtures. This is a synthesis, not a mandatory standard. Existing [behavioral UX](behavioral-ux-quality-2026.md), [component behaviors](component-interaction-behavior-patterns.md) and [microinteractions](microinteraction-state-and-polish.md) should be reused, not copied into each contract.
